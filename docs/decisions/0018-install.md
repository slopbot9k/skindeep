# 0018 make install and make uninstall

Status: accepted 2026-10-11, revised 2026-10-12 for portable commands,
2026-10-16 for the C port (decision 0036) and 2026-10-17 for an install
by make alone, with no shell script.

## Context

A user, or the user's agent, clones the repository on a Linux or macOS
machine and runs one command. It builds the checkout's programs and
puts three commands on PATH. Outside the checkout it writes nothing
else. `make uninstall` removes exactly the three commands.

## Decision

- `make install` builds `skinned`, `skinned-relay` and `skinc` (`make
  programs`) with `WERROR` empty, so a warning that a newer compiler
  adds does not stop an install, and make rebuilds only what changed.
  The tests and CI keep `-Werror`. It needs a C compiler and GNU make:
  on macOS Apple's Command Line Tools, which running `make` offers to
  install; on Linux the distribution's (`build-essential`, `gcc make`,
  `base-devel`). It says so when `CC` is not on PATH.
- It puts `skinned`, `claude-skins` and `codex-skins` in `BINDIR`,
  default `~/.local/bin`, each a symbolic link to this checkout's
  `build/release/skinned`. Run as `claude-skins` or `codex-skins`, that
  program runs as `skinned -- claude ARGS` or `skinned -- codex ARGS`,
  and run by a name with no slash it finds its own file on PATH, so
  `skinned-relay` and the checkout's `skins/` beside it. It warns when
  `BINDIR` is not on PATH.
- A file in `BINDIR` of one of those names that is not such a link is
  left alone and named. A wrapper an earlier `install.sh` wrote, the
  marker `# generated by claude-skins install.sh` on its second line, is
  replaced.
- It names the optional tools it does not find, one of each group
  enough: `gh` for GitHub's issue boards (decision 0029), and on Linux
  `curl` for Gitea's, `zenity` or `kdialog` for the folder picker,
  `pw-play`, `paplay` or `aplay` for sounds, and `pw-record` or `parec`
  for speaker capture.
- `make uninstall` removes every link in `BINDIR` to this checkout's
  `skinned`, and every wrapper with the marker, and nothing else.
- The recipes use only POSIX sh and the subset of `sed` that BSD sed and
  GNU sed share, as make runs them.

## Why

A link holds the checkout's path, so a moved checkout is repaired by
installing again, and uninstall tells its own from a user's file by
where the link points, with no state file outside the checkout. The
makefile already builds everything, so it installs too, and the
repository keeps no shell script. Prerequisites stay the user's to
install: the system's package manager knows the machine better than a
script does.

## Rejected

- A list of installed files kept outside the checkout: one more file to
  keep in step.
- Wrapper scripts, as `install.sh` wrote and `bin/` held: a shell
  script each, for what the program can see in its own name.
- Copying the programs into `BINDIR`: `skinned` finds `skinned-relay`
  and the checkout's `skins/` from where it lies.
