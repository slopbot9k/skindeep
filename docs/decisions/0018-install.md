# 0018 install.sh and uninstall.sh

Status: accepted 2026-10-11, revised 2026-10-12 for portable commands
and 2026-10-16 for the C port (decision 0036).

## Context

A user, or the user's agent, clones the repository on a Linux or macOS
machine and runs one command. It builds the checkout's programs and
writes three commands. Outside the checkout it writes nothing else.
`uninstall.sh` removes exactly the three commands.

## Decision

- `install.sh` checks for a C compiler and GNU make: on macOS, Apple's
  Command Line Tools (`xcode-select -p`); on Linux, `cc` (or `CC`) and
  `make` or `gmake`. It lists every missing one at once, with the
  package manager command on Debian, Ubuntu, Fedora, RHEL, Arch and
  openSUSE, or `xcode-select --install` on macOS. It installs none of
  them.
- It runs `make programs` with `WERROR` empty, so a warning that a newer
  compiler adds does not stop an install. make rebuilds only what
  changed. The tests and CI keep `-Werror`.
- It writes `claude-skins`, `codex-skins` and `skinned` into `BINDIR`,
  default `~/.local/bin`, each an exec of the same name under
  `<repo>/bin`. It warns when `BINDIR` is not on PATH. `bin/skinned`
  execs `build/release/skinned`, which writes its own log and finds
  `skinned-relay` beside itself.
- Every generated file's second line is the marker
  `# generated by claude-skins install.sh`.
- Install refuses to overwrite a file without the marker, and says so.
- It names the optional tools that are missing, each with the part that
  uses it: `gh` and `curl` for the issue boards, and on Linux `zenity`
  or `kdialog` for the folder picker, `pw-play`, `paplay` or `aplay` for
  sounds, and `pw-record` or `parec` for speaker capture.
- `uninstall.sh` removes every file in `BINDIR` whose second line is the
  marker, and nothing else.
- Both scripts are POSIX sh, and their `sed` is the subset that BSD sed
  and GNU sed share.

## Why

The marker makes uninstall exact without a state file outside the
checkout, and it also covers wrappers an earlier version wrote under
other names. A wrapper holds the checkout's path, so a moved checkout is
repaired by running install again. Prerequisites stay the user's to
install: the system's package manager knows the machine better than a
script does.

## Rejected

- A list of installed files kept outside the checkout: one more file to
  keep in step.
- Symlinks into the checkout: uninstall would have to resolve each link
  to tell its own from a user's file.
- Copying the programs into `BINDIR`: `skinned` finds `skinned-relay`
  and the checkout's `skins/` from where it lies.
